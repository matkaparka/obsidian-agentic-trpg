## 3. 气泡

### 3.1 挂在棋子上

- 气泡的锚点 = 这个角色的棋子在玩家窗口里的**屏幕位置**。
- `project/src/atlas/playerFrame.ts` 第 750 行附近已经有一段「世界坐标 → 玩家窗口屏幕坐标」的换算，用的是弹出窗口自己的镜头。复用它：
  - 由演出框在玩家窗口这一侧计算所有 PC 和可见 NPC 棋子的屏幕矩形；
  - 有变化时用 `postMessage` 发给 iframe，最多每秒 10 次；
  - 镜头、窗口尺寸、棋子位置变化时都要发。
  - iframe 已经有 `parent.postMessage` 往回报的通道。
- 棋子移动时，气泡要跟着移动，不能停在原处。
- 选择器、Atlas 内部字段只准出现在 `adapter.ts` 和 `playerFrame.ts` 里，这条规矩不变。

### 3.2 两种气泡

| | 心里想 | 说出口的话 |
| --- | --- | --- |
| 形状 | **云朵**，带 2–3 个由大到小的圆点连到棋子 | **直线边**（直角或小圆角的矩形），带一个尖尾巴指向棋子 |
| 内容 | **一句**第一人称心里话，见 §4 | 只放 `say`，不放行动描述 |
| 长度 | 建议 ≤ 22 个汉字，最多 2 行 | ≤ 40 个汉字，最多 3 行；超过就在句子边界截断加「…」，完整的话照样进事件 |
| 字号 | ≥ 30px（1080 画布） | ≥ 30px |
| 停留 | 出现后停 `T_thought` 秒 | 至少 4 秒，每字加 0.25 秒，最多 10 秒 |

- **配色**：
  - 两种气泡都用浅色底、深色字，这是漫画的读法，在深色地图上最清楚。
  - 两个角色各用一个低饱和的识别色描边，就用 `overlay.yaml` 里现有的 `accent_a` / `accent_b`。
  - 不用大面积高饱和的暖色。
- **出现顺序**：
  1. 玩家思考时，棋子上方出现一个小云朵，里面是动态的「…」；
  2. renderer 出结果后，换成心里话；
  3. 停够 `T_thought` 秒后，说话气泡出现，心里话的云朵缩小、淡出；
  4. 说话气泡停够时长后淡出。
  - 同一个角色同时最多显示 2 个气泡。
  - 没有心里话（超时、没有能上屏的）就跳过云朵，直接出说话气泡。不要出空云朵，也不要出「（没来得及整理）」。
- **摆放**：
  - 默认放在棋子上方。离地图区域边缘太近就翻到下方、左边或右边。
  - 两个气泡重叠时，后出现的那个换位置，简单的贪心算法就够。
  - 气泡**永远不能进主播区域**，也不能盖住字幕条。
  - 尽量不盖住另一名 PC 的棋子。
  - 气泡的尾巴始终指向自己的棋子。
- **NPC 和怪物**：这一轮先不给它们挂气泡（以后可以加一个 GM 工具 `npc_say`）。

### 3.3 表情

人物栏没了，表情改在**棋子头像**上体现：

- 角色换表情时，用 `atlas_update_token` 把棋子图片换成这个表情的头像。头像是从 `campaign-vault\sprites\<seat>\<表情>.png` 裁出来的圆形脸部。
- 裁剪框写在 `sprites\README.md` 规定的配置里，每个角色一个脸部框。
- 同一个棋子 3 秒内最多换一次，避免闪。
- 没有立绘时，用现在的 A / B 头像。
- 在 `sprites\README.md` 里说明：立绘只要求脸部位置一致，就能自动裁出头像。

这是我定的默认做法，用户 可能会改，所以加一个开关：`overlay.yaml` 里的 `token_expressions: true`。

## 4. 心里话必须是第一人称

**用户 指出的问题**：布拉姆的「心里想」读起来是第三人称。我查了日志：

- 真实对局里，看点标题绝大多数是第三人称的标签（薇克丝 65/73，布拉姆 58/60），例如「怕死牧师先给自己上祝福」「贪财盗贼先听水下动静」。
- 布拉姆有 6 条看点用自己的名字称呼自己，例如「布拉姆老是这样，永远挑最稳的打法」「布拉姆那套虔诚说辞，其实我也有点被传染了」。
- Gemini 的思考摘要大多是英文；它还把薇克丝叫成「Vex」。

**要做的（renderer）**：

- 新增一个输出字段 `bubble`：一句**第一人称**的心里话，≤ 22 个汉字，必须能在原文里找到依据（沿用现有的 quote 校验）。
- 写一个校验器，以下情况都判为不合格：
  - 出现自己的名字；
  - 用「他」「她」指代自己；
  - 是一句标签式短语（例如「X 先做 Y」这种）；
  - 超长。
- 不合格就让 renderer 重写一次；还不行，就从合格的 beats 里挑一条第一人称的；再没有就不出云朵。
- `headline`、全部 beats、`contrast` 照旧生成，**只进 helixus-link 事件和日志，不上屏**。
- 给 renderer 一张角色名对照表，例如「Vex / Vix → 薇克丝」，翻译时统一用中文名。
- 测试用例从日志里取真实的反例，就用上面那几句。

## 5. Helixus 要能看到细节

画面上只有气泡，所以事件要把「观众看到了什么」和「只有你知道什么」分开写清楚：

- `thought_beat`：改成每回合**一条**事件。内容依次是：上屏的那句心里话（标明「观众看到的」），然后是全部 beats（带标签）和 headline（标明「只有你看得到」）。urgency 规则不变：最高分的是 immediate。
- `contrast`：照旧。
- `decision`：内容是上屏的那句话（`say`），然后是**具体行为**：类型、目标、`detail`、移动到哪里。后面这部分标明「只有你看得到」。
- 骰子、移动的事件照旧。
- **AITuberKit 页面**：`minecraft.ts` 里 trpg 的提示词（第 434 行附近，「你看得到剧情、两名玩家的决定……」）要加一句：

  > 观众屏幕上只有角色头上的气泡（一句心里话、说出口的话）和地图；其余细节只有你知道，可以拿来解读、吐槽，但别整段念出来。

  改页面要遵守 §0：先问 用户 现在是不是在直播，不在播才放进去；在 `unity-stage` 分支本地提交；跑 `npx jest src/__tests__/features/helixus/minecraft.test.ts`，必须全过。
