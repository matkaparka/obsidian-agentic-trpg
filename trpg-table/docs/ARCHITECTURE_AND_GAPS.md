# trpg-table：框架梳理，和距离一场真正的 campaign 还缺什么

写于 2026-10-19（第二幕彩排中途）。依据是代码，不是印象：`src/table/loop.ts`、`gm.ts`、`player.ts`、`renderer.ts`、`view.ts`、`events.ts`、`link/server.ts`，AITuberKit 侧的 `src/features/helixus/minecraft.ts`，以及 `config/models.yaml`。

## 2. 数据流

LLM 之间**从不直接对话**。它们只通过三样东西耦合：规则层的状态、文字记录（transcript / 一步笔记）、事件总线。

```
                      ┌───────────────────────── 规则层（权威）─────────────────────────┐
                      │ HP / 位置 / 先攻 / 法术位 / 条件 / XP        ← 所有结算都走这里  │
                      └───▲──────────────────────────────▲──────────────────────────────┘
                          │ 工具调用                      │ executePlayerAction
                          │                               │（先走到目标旁边再做动作）
  ┌───────────────┐  ask_player(座位, 提示)       ┌───────┴─────────┐
  │ GM  Haiku     │ ──────────────────────────▶ │ 玩家 A DeepSeek  │ 只看公开视角
  │ 看全部/含秘密  │ ◀── 上一步的结果（结算文字）── │ 玩家 B Gemini    │ ──┐ 思维链
  └──┬──────┬─────┘                               └─────────────────┘   ▼
     │      │ director_note / secret_hint            决定 JSON      ┌──────────┐
     │      │                                                      │ renderer │ DeepSeek chat
     │ narrate                                                     └────┬─────┘
     │      │                                       bubble（上屏）/ beats（只给 Helixus）
     ▼      ▼                                                          │
  ┌──────────────────────────── EventBus（事件总线）◀─────────────────┘
  └───┬─────────────────────┬──────────────────────────┬────────────────┐
      │ SSE :8099           │ :8098 /events 轮询         │ TTS            │ Atlas 同步
      ▼                     ▼                          ▼                ▼
  overlay（Atlas 玩家窗口） AITuberKit 页面 = Helixus   百炼合成        地图 token / 先攻 / 迷雾
  字幕·气泡·卡片·状态标签    点评 → GSV 配音 → Unity 舞台  → overlay 播放
                              ▲
                              └── POST /command（建议）→ GM 用 respond_suggestion 表态
                                  （页面的提示词现在已经不让他发这个了，通道留着没用）
```

逐条交互：

1. **GM → 玩家**：`ask_player(seat, prompt)` 只做一件事——设定「轮到谁」和一句提示，提示在玩家视角里显示成「GM：……」。玩家同时看到 GM 刚才那一段旁白。
2. **玩家 → GM**：玩家行动被规则层结算后，`buildGmNote` 生成一段「X 这一回合：……结算：……」，**作为下一次 GM 调用的「上一步的结果」**。这是 GM 知道玩家干了什么的唯一正式通道（另外还有 transcript 里的一行）。
3. **玩家 → renderer → 观众 / Helixus**：思维链进 renderer；bubble 上屏，beats / headline / contrast 只发给 Helixus。思维链原文只写本地日志。
4. **GM → Helixus**：`director_note`（导演稿，Helixus 当作自己的决定）、`secret_hint`、旁白。观众只看得到旁白。
5. **Helixus → GM**：只有 `POST /command` 的建议，不可信文本，GM 自己决定采不采纳。现在页面提示词里没有这条，实际上没人发。
6. **玩家 ↔ 玩家**：只能看到对方最近 5 句 `say`。没有直接对话的通道。
7. **GM → 规则层 → Atlas**：GM 用工具改状态；token 位置、血量、先攻都是规则层推给 Atlas 的。

## 3. 一步是怎么走的

`TableLoop.step()` 是状态机：

- 战斗中：按先攻。轮到怪物 → `runGm(mode: monster)`，GM 结算；轮到玩家 → `runPlayer`。
- 探索中：如果 GM 上一轮 `ask_player` 过某个座位（`currentSeat`）→ `runPlayer(那个座位)`；否则 `runGm(normal)`。
- ~~所以探索阶段「轮到谁」完全是 GM 这个 LLM 说了算。~~ **2026-10-19 起不是了**：探索按回合计走（`src/table/roundClock.ts`），每轮每个 PC 一次 → 世界回合 → 关轮，GM 点错人会被改回来。见第 4 节和 `HANDOFF_ROUNDS.md`。

玩家一步（`runPlayer`）：构造公开视角 → 玩家模型出决定 → 台词开始合成 → renderer 出看点 → 发 `thought` / `thought_beat` 事件 → 等云朵和心里话念完 → 发 `decision` 事件、台词出声 → 等念完 → 规则层结算（带 `cell` 先走位）→ 写 `history` → 把结算文字存成下一步给 GM 的笔记。

GM 一步（`runGm`）：最多 6 轮「模型 → 工具 → 结果」，`narrate` 的文字进字幕和配音，`ask_player` 结束这一步。

已有的防乱机制：

| 机制 | 管什么 | 状态 |
| --- | --- | --- |
| `gmSteps >= 3` | GM 连续 3 步没交出行动权 → 桌面按「上一个行动的人的另一个」轮到玩家 | 在跑 |
| `monsterSteps >= 2` | 同一只怪同一回合 GM 两次没推进 → 自动过回合 | 在跑 |
| 回合计（取代了 `rotateAskedSeat`，后者已删） | 探索每轮每个 PC 只行动一次，世界回合没登记完 `ask_player` 被拒；GM 点错人改成下一位 | 在跑（18:04 重启后） |
| 玩家决定的调用上限 `player_timeout_ms` | 玩家模型那一次调用超过 75 秒 → 保守默认行动，这一轮照样往下走 | 18:10 写好、已测，**进程里还没有（要重启）** |
| 一幕节奏提醒 `scene_nudge_rounds` | 一幕走到第 12 轮还没结束，GM 的每次提示里加「该推进了」，之后每 4 轮加重 | 同上，**要重启** |
| 单次 LLM 调用超时 | `step_timeout_ms` 180 秒 | 在跑 |
| 玩家 JSON 解析失败 | 重试 1 次 → 保守默认行动 | 在跑 |
| 看点 7 秒预算 | 超时只显示决定、不显示云朵 | 在跑 |
| 费用止损 | `scripts/cost-guard.mjs`（外部脚本，按 usage.jsonl 累计，超线 POST /pause） | 在跑，但是外挂的 |

## 4. 回合计：现状和该怎么做

> **更新（2026-10-19 18:10）：回合计已经做完并在真模型上跑过**（Haiku 当 GM 跑了 4 轮，`world_act` 用上了；说明见 `HANDOFF_ROUNDS.md`）。下面「现状」仍是落地之前的样子，留着当对照；建议 2、3 已按下面的方式做了：2 做成**玩家模型调用的上限**（75 秒），不是整回合 45 秒——正常一个回合光看点、配音、停顿就要一分多钟，整回合限时会天天触发；3 做成**一幕走到第 12 轮后 GM 提示里的提醒**（按回合计的轮数，不是墙上时间）。4 只做了一半：1 轮 ≈ 1 分钟只用在状态到期上，暮色、篝火余烬用剧本 `## 环境` 的条目演出来，没有真正的昼夜 / 光源。
>
> 原文：写这份文档的时候（15:11 起）另一个会话「TRPG 回合制机制」已经在做回合计：新文件 `src/table/roundClock.ts`（探索按固定顺序各动一次 → 世界回合 → 关轮；剧本新增 `## 环境` 段；GM 能登记倒计时），同时在改 `loop.ts` / `engine.ts` / `content.ts` / `types.ts` / `events.ts`。
> 下面「现状」是我读代码时看到的、那边落地之前的样子；「建议」里的 1 它已经在做，2（回合时限）和 3（场景软时限）我没看到。**以那边的实现为准，我没动这些文件。**

**现状（用户 说得对，这是最明显的缺口）：**

- 战斗里有：`engine.combat.round` 每轮 +1，overlay 底栏显示「第 N 轮」，先攻条高亮当前行动者。
- 探索里**没有**：`TableLoop.round` 这个字段从 `= 1` 起就没人动过，overlay 在探索时只显示「探索」。没有「本轮谁动过、谁还没动」。
- 后果在今天的彩排里看得到：GM（Haiku）连续 4 次把行动权交给维斯坡伊，萨珀特菲整段没戏。`rotateAskedSeat` 是事后补的，只管「连续 2 次」，不是回合制。
- 也没有任何**时间**：不管是墙上时钟（单个玩家一回合想多久）还是游戏内时间（过了几分钟 / 几个小时）。

**建议的做法（等 用户 定）：**

1. **探索轮**：一轮 = 每个清醒的玩家各行动一次。桌面记「本轮已行动的座位」。GM 想点已经动过的人而另一位没动 → 改点没动的那位（现在的轮换就是这个的弱化版）。两个人都动完 → 轮数 +1，发一个事件。overlay 显示「探索 · 第 N 轮」，GM 的提示里加一行「本轮已行动：X；还没动：Y」。存档里存这两个数。换场景重置。
2. **回合时限**：玩家一步超过 N 秒（建议 45）→ 用保守默认行动、标记「这回合发呆了」，不让一个慢模型把整桌拖住。现在只有 180 秒的单次调用超时，Gemini pro 实测出现过 197 秒。
3. **场景软时限**：一幕超过 M 轮还没到出口条件 → 在 GM 的提示里加一句「该给出口了」，再往后给 Helixus 一条 `secret_hint`。今天第二幕在这个进程起来之后跑了 25 分钟、$0.20（之前还有一段），还没进第三幕。
4. **游戏内时间**（可选，另一个层面）：1 个探索轮 ≈ 1 分钟之类，长休 8 小时，让「天色在变晚」「火把还剩多久」「营地的火」有数。要不要做看你。

我对「回合计」的理解是 1 + 2（计数和时限），3 和 4 是顺手的。如果你要的是屏幕上看得见的倒计时圈，那是 2 的显示部分，也能做。

## 5. 距离一场真正的 campaign 还缺什么

按「没有它这场戏就不成立」到「有了更好」排。

### A. 没有就跑不长

1. ~~回合结构~~ **已做**（见第 4 节）。
2. ~~战役记忆~~ **2026-10-19 晚已做**（`memory.ts`：每幕前情 + `note_fact` 世界事实，GM 看全文、玩家只看公开版，进存档；见 `HANDOFF_CAMPAIGN_STATE.md`；要重启才生效）。下面是做之前的现状：GM 只看得到：总览前 700 字 ＋ 当前这一幕 ＋ 最近 14 条桌面记录。上一幕的结局 14 条之后就没了；`end_scene` 的 summary 只是 transcript 里的一行。存档里有个 `sceneFlags`，永远是空的，没人读写。玩家更惨：只有 GM 刚才那一段、最近 10 条事件、队友 5 句话、自己 3 次行动。**两幕之前发生了什么，两边都不知道。** 需要：前情摘要（每幕结束由 GM 写、进每次提示）、任务线 / 日志、世界标记（谁欠谁、哪个 NPC 知道什么、哪条路被堵了）。
3. **GM 和规则层的一致性**。GM 只能通过工具间接问世界，没有「查这一格是什么 / 这个地标能不能进」的工具。规则层拒绝了某个动作，GM 就自己编一个理由——今天的例子：红帐、南侧帐篷、北侧帐篷的格子在地图数据里被标成**障碍**，棋子进不去，GM 于是编出「一堆木箱绳结把门帘堵死了」，萨珀特菲砍了一轮绳子。这不是模型笨，是数据和叙事对不上。需要：地图数据和剧本对一遍（谁能进、谁不能进）、让 GM 能查格子。
   - **2026-10-19 核实**：`canStandAt` 对红帐中心 (10,8)、红帐角 (9,7)、南帐 (6,9)、篝火坑 (8,6) 都是 false，属实；而且原来玩家走向这些格子时**整次行动作废**（`move.ok=false` → 抛错 → 结算只剩「行动未执行」），连带检定也没做。「规则层拒绝时把原因交给 GM」其实一直有（结算文字里带「不能站在…」），GM 看到了还是选择编障碍。
   - **地图数据 18:19 已改**：红帐、南侧帐篷、北侧帐篷里面都能进了（火坑和树仍是障碍），见 `HANDOFF_CAMPAIGN_STATE.md` §1。
   - **18:10 已改（要重启才生效）**：玩家的 cell 落在障碍 / 水面时，改走到离它最近的合法格（一样近的取离自己近的一侧），行动照做，结算里写「红顶大帐内 (10,8) 是障碍或水面，站不进去，改走到 …」。地图数据本身还没动（用户 说先别修）：红帐里有战利品箱，剧本要它能进去的话得把红帐里面的障碍去掉。
4. ~~卡住检测~~ **2026-10-19 晚已做**：场景 md 的 `## 节拍` / `## 自动出口`（确定性，满足了桌面让 GM 收尾，GM 不收桌面替它收）+ 进度导演（Haiku，每 2 个探索轮对照剧本判断，桌面强制执行）；见 `HANDOFF_PROGRESS.md`。下面是做之前的现状：今天第二幕的现象：一个人原地打转、GM 续写障碍。除了 `gmSteps` 和 `monsterSteps`，没有「这一幕太久没进展」的检测。**18:10 加了按轮数的提醒**（第 12 轮起，要重启才生效）；还没有的是「同一个人连续几轮做同一件事」这种更细的检测。

### B. 一场戏该有的东西

5. ~~物品、金币、战利品~~ **2026-10-19 晚已做**（`inventory.ts`：背包 + 铜币，GM 工具 `give_item` / `give_gold` / `take_*`，剧本 `## 战利品` 清单，玩家 `item` 行动能喝药水，面板有金币；见 `HANDOFF_CAMPAIGN_STATE.md` §3；还没有商店、负重、魔法物品效果）。下面是做之前的现状：运行时没有背包。剧本里写了「9 gp、矮人银衣扣」，但 GM 没有「给物品」的工具，规则层也没有物品栏；`item` 这个行动类型没有对应的结算。商店、消耗品（治疗药水）、负重、魔法物品奖励都没有。
6. **游戏内时间和环境**。没有时钟、昼夜、光源、天气、赶路时间；长休没有「夜里被打断」的可能。第二幕的「天色在变晚」只是旁白一句话。
7. **玩家之间的戏**。两个角色互相只听得到最近 5 句台词，没有「商量一下怎么办」的环节，没有意见分歧、传纸条、各自的秘密。人设里写的「互相欠着一条命」没有任何机制承载。
8. **队伍太薄**。只有 2 个 3 级角色，没有 NPC 同伴 / 雇佣兵，GM 也不能临时操控友军（Gundren 被救之后怎么办？）。
9. **战役的形状**。现在是一个 5 幕 one-shot：没有中心地点、没有跨冒险的线（黑斗篷的钩子只是留了个口）、没有「上回说到」、没有两局之间的休整、升级只是自动重跑构建器（没有玩家选择）。

### C. 内容和规则的规模

10. **怪物只有 15 种**（SRD 有三百多种）；没有传奇动作 / 巢穴动作；范围法术的目标靠 GM 手填；召唤、持续区域、传送、变形都是「GM 裁定」。
11. **视野**：规则层不管视线、黑暗、隐匿的位置关系；迷雾是 GM 手动 `reveal_area`。
12. **只有一份冒险**，地图资源（LMoP 配套包）的许可证没核实。没有遭遇表、NPC 名册、讲义。

### D. 直播层

13. **观众互动**：观众现在影响不了任何东西。没有投票、「祝福 / 灵感」之类的打赏钩子、迟到观众的前情提要。
