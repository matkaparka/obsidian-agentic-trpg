# 回合计（2026-10-19）

问题：战斗里有先攻和轮数，但**探索里没有任何回合概念**——谁行动全靠 GM 点名，存档里 `round` 一直是 0；
场上拴着的狼、水位、天色这些“自己会动的东西”从来没有行动过；有回合数的状态在战斗外永远不会到期；
战斗外一个 PC 用过一次动作之后一直是“本回合动作已用”，要等下一场战斗才恢复（我读存档时 player_a 就带着 `actionUsed: true, dashed: true, movementUsed: 100`，是上一次疾走留下的）。

## 现在怎么走

**桌面第 N 轮**（`RoundClock`，探索和战斗共用一条计数，换场景从第 1 轮重数）。每一轮里每个能动的角色和环境各行动一次：

| | 一轮的顺序 |
| --- | --- |
| 探索 | 维斯坡伊 → 萨珀特菲（固定顺序，倒下的跳过）→ **世界回合** → 关轮 |
| 战斗 | 先攻顺序里每个人（引擎管，和以前一样）→ **世界回合（只有环境，生物已经在先攻里）** → 关轮 |

- **世界回合** = 场上还活着的非 PC 生物（战斗外）+ 这一轮到点的环境条目。清单附在 GM 那一步的提示里（探索：和“结算最后一个 PC 的行动”是同一次调用，不多花一次模型调用；战斗：先攻一圈走完后单独一次，没有到点的环境就不调用）。GM 对每一项用 `world_act` 登记；没登记完 `ask_player` 会被拒。GM 漏了的，桌面替它记成“没动静”，轮照样往下走，所以不会卡死。
- **GM 点错人**：探索里 `ask_player` 点的不是回合计认的下一位，会被改成下一位，返回里告诉 GM。原来的 `rotation.ts`（同一个人最多连续两次）已经删了，被这个取代。
- **战斗外的回合**：每个 PC 的回合开始 `beginExplorationTurn`（动作 / 附赠 / 反应 / 移动恢复），结束 `finishExplorationTurn`（狂暴要有人维持、带豁免的状态回合末再豁免）；一轮结束 `advanceExplorationRound`（**战斗外一轮≈1 分钟 = 10 个战斗轮**，有回合数的状态和效果按这个往前走）。
- **环境条目**：剧本场景 md 里 `## 环境`，一行一条 `- 名字｜节奏｜效果`。节奏写 `每轮` / `每 3 轮` / `第 8 轮`（只那一轮）/ `第 3 轮起每轮` / `第 3 轮起每 2 轮`；行里带 `[秘密]` 的玩家和观众看不到（回合条不画、事件不带名字）。GM 也可以随时 `set_timer` 登记倒计时（涨水、援军、毒发）、`cancel_timer` 取消，到点自己进世界回合清单。
- **画面**：右下面板标题改成“第 N 轮 · 探索/战斗”，旁边的回合条在探索里也显示：两个主角、场上看得见的生物、到点的环境（金色方块）；行动过的压暗 + 右下角绿点，下一位白圈；新的一轮标题闪一下。截图在 `docs/shots/rounds/`。
- **存档**：`table.json` 多一个 `clock` 字段（轮数、本轮谁动过、世界回合登记、环境条目和 GM 倒计时的进度）；老存档没有就按这个场景从第 1 轮数起。
- 第二幕（`02-forest-camp.md`）我写了两条示范环境：暮色（每 4 轮）、篝火余烬（每 5 轮），都取自该场景 GM 秘密里已有的内容，不合适直接改文件。

## 已知取舍

- 探索里固定 A → B，不掷先攻；以后要掷就改 `RoundClock.nextSeat`。
- 探索一轮 ≈ 1 分钟只用在状态到期上；旁白不会因此说“过了一分钟”。
- 环境条目的节奏用的是桌面轮号，战斗一轮（6 秒）和探索一轮（1 分钟）都算一轮；写“每轮”的水位在战斗里每 6 秒涨一次，写之前想一下。

1. **技能名校验**（`src/table/checkStat.ts`）：`request_check` / `roll_check` 的 skill 原来不校验，GM 传「动物驯养」之类不在技能表里的名字，引擎当成属性、modifier 是 NaN，骰子公式变成 `1d20nan`（真 GM 出现过 3 次，都靠自己重试）。现在认英文 id（大小写 / 空格 / 驼峰）、属性全称、引擎的中文名、官方中文译名和常见别名；不认识就回错误并列出可用清单。
2. **世界回合清单格式**：`[world:ID]` 改成 `id=ID`，`world_act` 容忍 `world:` / `id=` / 方括号前缀（Haiku 会整串抄，被拒一次）。
3. **走向障碍格不再整次作废**：玩家的 cell 落在障碍 / 水面 / 地图外时，改走到离它最近的合法格（一样近的取离自己近的一侧），行动照做，结算写「红顶大帐内 (10,8) 是障碍或水面，站不进去，改走到 …」。原来 `move.ok=false` 会抛错，整次行动（包括检定）作废，GM 只看到「行动未执行」，于是编出堵门的木箱（第二幕打了一轮绳子的原因）。地图数据没改。
4. **一幕节奏提醒**：`limits.scene_nudge_rounds`（默认 12，0 = 关）、`scene_nudge_every`（默认 4）。探索 / 谈话里一幕走到这一轮还没结束，GM 的每次提示里加「【场景节奏 · 第 N 次提醒】……别再续写新障碍，让他们看见往前走的路」，带出口条件；战斗里和收尾幕不提醒。
5. **玩家决定的调用上限**：`limits.player_timeout_ms`（默认 75 秒）。超时 / 服务出错就用保守默认行动、这一轮照样往下走（原来是 180 秒，超时抛错、整步重来、GM 白被再叫一次）。**不是整回合限时**：看点 + 配音 + 停顿正常就要一分多钟。
6. **GM 的记录窗口**：回合计往记录里加的「—— 第 N 轮结束 ——」分隔行删了（回合计上下文里已经有轮数），窗口从最近 14 条放宽到 20 条。实测一轮里 gm / player 只占 4–6 条，世界回合那几行会占掉窗口三分之一，原来的 14 条大约只够两轮。
